# Historic places, gardens and public walks

The existing categories and screen layout are unchanged. Historic hotels, inns and houses can be history subjects when supplied evidence supports that significance. Public gardens, promenades and riverside paths can appear under walking when their text supports actual walking use. A garden name alone does not establish a walking route; route length, difficulty, access and accessibility are not inferred. Ordinary hotels do not become attractions merely because they sit in a historic town.

## Stable nearest-first browsing

Each existing Explore category sorts its deduplicated cards by straight-line distance from the guide's search point, with unmapped items last and alphabetical ties. This is the latest GPS search point for a nearby guide, or the selected place's reference point for a named search. It does not watch live GPS, reroute, continuously reshuffle cards or request another AI guide to sort them. Displayed distances use the same calculation as ordering. Food and stay pages inherit the selected search coordinates for the same nearest-first behaviour; selecting a local trial area without a point uses its centre. The voice-trigger queue is independent of this browsing order.

# Local search boundaries

City Explore searches use a 10 km straight-line radius (previously 40 km).
The existing final coordinate check applies to every source, including travel
listings and subject searches. Reviewed Buxton supplements additionally require
the search point to be within 3 km of the individual place, and respect any
smaller requested radius. Priority never overrides the geographic boundary.
Manchester therefore cannot include these Buxton additions. Distances remain
straight-line distances, not driving times or municipal boundary polygons.
Guide version 13 identifies this scope change; previously displayed guides need
a fresh search after deployment.
